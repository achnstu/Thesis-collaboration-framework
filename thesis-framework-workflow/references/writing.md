# 写作与证据

本文件集中语言规则、各部分的论证职责与写作方法，[学术改写对照](writing-examples.md) 集中全部教学示例。按任务只读相关小节，无需沿多个文档重复查找。以作者认可的当前稿件、目标规范及真实证据为准。

## 从框架到章节

1. 写一句研究问题、一组具体贡献以及各贡献对应的证据。比较对象、实验条件和证据边界需可追溯。
2. 建立“章—节—问题—方法—材料—图表—预期结论—缺口”映射。每章承担独立功能，研究章节通常有引言、方法、实验、结果和小结，结构按学科与导师要求调整。
3. 将多个章节共用的概念、理论、材料或研究方法放在合适位置，避免重复。实验研究可集中介绍模型、评价指标和实验协议，算法改进研究可先建立基线再说明增量，其他学科按研究设计组织，不强制基线或统一实验协议。
4. 小论文是素材，不是直接复制模板。逐段归位至大论文框架，核对新旧实验口径、图号、公式与引用。文献综述比较多条研究路线，以文献证据提出研究缺口，避免由单篇论文支配全文。
5. 每段有明确作用，按需要组织研究条件、比较对象、证据、解释和必要限制。不同段落可承担定义、方法推导、文献综述或讨论，不机械套用同一种顺序。解释须符合机制和证据，不将相关性写成因果。中文表达和结果论证见下文相应章节。

## 从研究问题到各部分写法

语言规则贯穿全文，章节写法决定哪些信息应在何处展开。先整理当前证据能回答的问题，再确定主张、章节职责和段落顺序，最后调整句子。准确、自然的原文不因采用这套方法而重写，局部任务也不要求补齐所有章节。

| 部分 | 主要回答什么 | 需要呈现的关系 |
|---|---|---|
| 标题 | 研究对象和核心工作是什么 | 对象与贡献匹配，避免超出验证范围的定性 |
| 摘要 | 做了什么，怎样验证，发现了什么 | 问题、关键方法、验证范围、主发现及有边界的含义 |
| 引言与综述 | 为什么研究，这项工作补充什么 | 具体问题、已有路线及证据、尚未解决的关系、本文研究问题 |
| 方法与公式 | 怎样处理该问题，设计为何成立 | 目标、设计作用、定义或模型、关键假设和实现对应 |
| 数据与评价 | 比较为什么成立 | 数据来源与划分、基准信息条件、重复单位、指标及聚合 |
| 结果 | 观察到了什么 | 关键比较、数字、趋势、取舍与必要例外 |
| 讨论 | 这些发现意味着什么，解释能到哪一层 | 与问题及文献的联系、合理解释、已验证机制、适用范围 |
| 结论 | 研究问题得到了什么回答 | 完成的工作、证据支撑的主要判断、仍需解决的问题 |
| 回复信及附属文件 | 如何回答质疑或传达同一研究 | 对问题直接作答，与正文事实一致，按独立阅读需要取舍 |

这张表是职责映射，不要求每篇都有独立同名章节。结果与讨论合并、理论推导、定性研究或综述均按目标文体调整。研究材料先整理清楚，摘要和结论通常在主发现确定后回写，文档中的出现顺序不必等同于实际起草顺序。

### 让前后部分真正接上

引言提出的问题，应能在方法和评价中找到对应设计，在结果中找到证据，在讨论及结论中找到回答。不能引言强调安全、结论强调寿命，而实际只比较能耗。不同研究问题可分段或分节展开，只有相关证据时才加入额外主张。

综述比较问题与方法关系，保留具体研究的作者归属和支持它的引文。研究不足应由已有文献和本研究目标推出，不为衬托自己而笼统否定前人。引言末段说明本文做什么、关键设计作用及验证范围，不预先复制全部结果表。

方法先解释设计要解决什么，再给定义、公式和可复现细节。公式与符号释义连接在设计作用之后，评价协议让读者判断比较是否公平。结果直接呈现发现，讨论解释其与研究问题的关系。未有因果证据时保留推测程度，不用“由于”替代机制验证。

各部分可以复用术语和核心事实，但承担不同作用。结果给证据细节，讨论说明解释，结论概括回答，摘要压缩完整信息链。统一事实不等于四处复制同一句话。完整连贯写法见 [同一案例](writing-examples.md#摘要结论与结果的连贯示例)。

## 接手与修改顺序

先确认当前作者稿件、目标读者和本轮范围。作者已在 Word 中手改时，以指定的当前稿件为依据，同步规划与中英对照。只要求文字版时给出可替换文字，不写回未授权的文件。模板和历史对话只帮助组织表达，当前证据决定具体内容。

每轮按“事实与范围 → 本节要回答的问题 → 段落作用 → 句子表达 → 对象与页面”检查。先解决论证缺口，再压缩文字。保护公式、编号和引用的方法见 [Word 工具](word-tooling.md)，正文、SI 与回复联动见 [返修流程](revision-workflow.md)。

## 段落组织与合并

先判断相邻段落是否共同回答一个问题，再决定句子怎样表达。**短句不等于短段，拆句不等于另起一段。** 同一比较中的发现、关键数字及解释，或同一设计的目的、做法及评价安排，通常组织为一个连贯段落。相邻公式的新符号释义也可集中说明，不因换了一个符号、一个指标或一个动作就分段。

审查时逐对看相邻段落：合并后若主旨仍明确、衔接更顺，就优先合并，删去重复引导语并保留条件、归因和结论强度。只需标点或简短过渡即可连接时，不额外添加总结句。英文长句拆短后，优先留在原段内，让多句共同完成同一论证。

研究问题、论点或段落作用确实变化时再分段，例如从观察结果转入独立的机制讨论，或开始回答另一问题。内容过长时按子问题组织，不把全文压成大段，也不按固定句数、字数或视觉留白机械分段。日常研究说明同样按问题组织，避免每句单独成段，确需逐项操作或并列比较时再用列表。

## 中文学术表达与论证

先以作者认可的当前稿件校准术语、句长、详略和图表引述，结合内嵌 [humanizer-zh](../embedded/humanizer-zh/SKILL.md) 与 [lieflat-less-ai-tone](../embedded/lieflat-less-ai-tone/SKILL.md) 识别具体问题。以清楚、自然、正式的学术中文为默认，不强制口语化、短句或被动句，不以词语命中、标点和检测分数判断文本来源。

以研究对象或变量为主语，直接写动作、条件与结果，减少没有独立信息的评价和空泛收尾。跨段以问题、对象或发现承接，不机械套用“首先、其次、最后”。各段可以承担定义、推导、综述或结果分析等不同职责。只有因果证据充分时才用“导致”等确定归因，观察到共同变化不能升级为机制证明。

扩写只补读者理解所缺的信息，例如设计理由、参数作用或比较能排除的混杂，不设增删字数目标。准确自然的原文可以保留。标点服从当前作者与目标规范，本框架形成时的作者偏好论文不用分号，迁移时不自动推广为所有作者的硬规则。

## 英文科技论文的语言审查

以作者认可的英文稿为风格基准，先区分学术通用原则与该作者的语言偏好。以下短句、被动语态、第一人称和分号约定体现本框架形成时的作者偏好。迁移到其他作者或期刊时，应按其现稿、任务要求与投稿规范调整，不能把偏好当作所有领域的硬性要求。基于中文语料的内嵌润色规则只提供保留事实、作者声音与最小修改等通用原则，不把其中文触发词直接用来判断英文。

- 优先保留准确、简洁的原文。长句包含多个动作、条件或比较而增加阅读负担时，按逻辑拆成短句，每句突出一个意思。一个意思能清楚地用一句表达时不机械拆句。句子衔接须明确，避免代词指代不清，也不把连贯的段落拆成零散条目。
- 方法、处理过程和评价安排优先考虑自然的被动语态。正文一般不用 I 或 We 作主语，可用研究对象、方法或结果作主语。保留清晰、自然的主动句，不为追求被动语态扩大修改范围或改变施事、目的和事实。
- 文献综述围绕研究问题和方法关系组织段落，不按篇目堆砌或无依据地分段。具体研究保留作者署名及对应引文，不能为精简或被动语态将其匿名化。多篇研究的概括可用合适的被动表述，归属和引文均须核对。
- 修改后逐项核对比较对象和方向、条件、设计目的、数值、单位、归因、时态与结论强度。结果段的关键比较应交代数值对应关系，不把观察结果、合理解释和已验证机制混为一谈。术语、指标名称、缩写和标题格式以作者当前稿件为准并保持一致。
- 删除重复、制作过程和无信息量的防御性文字，保留影响方法理解、复现或比较的条件。新增说明应紧接相关证据，避免生硬追加总结。未经明确要求不使用分号。
- 用户要求前后对照、文字版或先审批时，只提供对应位置的原文、建议文字和必要理由，待批准后才修改指定稿件。局部授权不等于全篇改写或排版授权。修改后检查相关文件是否需要同步，按实际授权执行。

摘要与正文在需要时各自首次定义缩写，单次出现的术语通常直接拼写。关键术语、指标和标题格式沿用现稿，不为避免重复换成含义不同的近义词。中英对照核对条件、否定、时态、数值和归因，不逐字翻译中文连接句。

## 摘要、结论、结果与公式释义

先确定各部分需要回答的问题，再选择详略。方法与示例不规定固定句数或顺序，具体完整示例见 [连贯案例](writing-examples.md#摘要结论与结果的连贯示例)。

### 摘要：形成一条完整而有取舍的信息链

摘要应独立交代具体问题、关键方法、验证范围与主发现。先从正文中确定最想让读者记住的科学判断，再决定哪些背景、方法和数字不可少。重要的是读者读完能重建“为什么这样做、怎样判断效果、实际发现什么”，而不是一句对应一个固定标签。

**从问题引出方法。** 背景只保留理解对象和难题所需的信息。接着写新增设计做什么、它如何针对该问题。仅写“融合 A、B、C 构建框架”没有解释各部分作用，也不能代替贡献。研究尚未证明某机制时，方法句写设计目的，不提前写成已获得的效果。

**从方法接到证据。** 用适当篇幅交代验证对象、比较基准及必要条件。它们决定结果能支持什么。仿真、记录数据回放、硬件在环和实际设备试验准确区分，未做的验证不补入。样本数、独立重复或数据划分在影响主张理解时保留，不把全部实验协议挤进摘要。

**从证据选主发现。** 数字量化的是判断，不是展示工作量。先判断研究主张由哪项发现支撑，再选最有信息的指标与比较。涉及两个数据集或工况时，让每组数字与对应条件一一绑定，必要时拆句。重要取舍不能被只报有利指标掩盖，某条件最大降幅不能写成全部测试的共同效果。

**最后回答研究问题。** 末句可以概括用途或意义，但应落在实际验证范围内。已给出清楚回答时，不必追加“提供新范式”等空泛收尾。也不机械列出所有局限，选择会改变摘要主张解释的条件即可。准确说明范围，比先拔高再追加一串否定更清楚。

| 写摘要时的决定 | 取舍原则 |
|---|---|
| 背景和不足 | 对象与具体问题清楚即可，领域不足有文献依据，不用宏大背景填篇幅 |
| 方法细节 | 保留区别于现有方法且能解释主发现的设计作用，次要实现留正文 |
| 验证条件 | 说明读者判断主张所需的基准、数据或实验类型，不混淆证据层级 |
| 主结果 | 选回答研究问题的关键比较，保留重要代价，数值与指标及条件对应 |
| 意义 | 由主发现推得，避免扩大到未测对象、真实寿命或实际部署 |
| 字数不足 | 合并相邻功能、删重复背景和次要数字，不牺牲比较对象或关键条件 |

可选的信息链为“具体问题 → 方法及作用 → 验证范围 → 主要发现 → 有边界的回答”，不是固定五句。问题可与方法同句，复杂结果可用数句表达。摘要独立判断缩写需要，正文另行处理首次定义。定性、理论和综述论文按其证据说明主要发现或论证，不硬加百分比、基准或实验。

交稿前把摘要每个实质性主张映射到正文位置，核对对象、条件、数字、比较方向与确定程度。只有待润色文字时保留原有主张，将需证实之处单独指出，不用写作步骤补造事实。

### 结论：回答研究问题，展望补上真实缺口

结论面向已经了解研究的读者，说明完成的工作带来了什么认识。先回到引言提出的问题，再整理主要回答及其证据。不能只把摘要拉长，也不按“图 1 说明、表 2 表明”的顺序复述结果。

**开头交代问题、方法和完成范围。** 简明说明研究对象、针对的关系、关键设计及实际验证。不重写整段背景，也不一句“提出并验证了某方法”结束。开头需要几句由信息量决定，导师对某稿件提出约四句的安排不推广为统一要求。

**主体按发现组织。** 每项结论先给研究问题的回答，再保留足以支撑它的比较、数值或理论依据，最后在需要时说明意义。例如“新增信息在哪些条件下有效”“代价是什么”“哪项证据支持解释”各有不同作用。定量论文保留关键数字，但不复制整张表，理论或定性论文保留关键推导、主题及反例。

**将确定程度放在判断中。** 均值改善不等于每次都改善，一组消融不包办全部机制证明，动态代理不等于实测退化。对重要例外和权衡，写出它怎样改变适用判断，不隐藏也不无差别铺陈。已在结果和讨论中建立的解释可以概括，结论不首次提出新的实验、数据或已验证机制。

**展望从具体缺口推导。** 每项建议连上“当前缺什么证据 → 拟做什么 → 要回答什么问题”。只写“增加数据、优化算法、开展应用”无法看出工作与本研究的关系。只列最重要且真实存在的缺口，避免把将来工作写成承诺必然改善，或用自我辩护式否定收尾。

| 当前实际情况 | 有对应依据时可提出的验证 |
|---|---|
| 只测功率变化或应力代理 | 用退化模型、老化数据或试验研究代理与退化的关系，区分各自证据 |
| 新数据上重新训练后测试 | 增加参数冻结的跨数据测试，研究无需再训练时的适用范围 |
| 新增特征同时增加输入维数 | 设置有意义的等维对照，进一步辨别信息内容与输入规模的作用 |
| 计算时间只在仿真主机测得 | 在目标硬件结合控制间隔和实际延迟验证执行可行性 |

这些是针对真实情况的选项，不是每篇必须承认的四项不足。展望位置可以在讨论或结论，按期刊结构和现稿处理，不两处重复展开。

| 相同事实 | 摘要中的作用 | 结论中的作用 |
|---|---|---|
| 方法使用什么信息 | 使读者快速理解研究做法 | 回答该设计带来了什么认识，贡献由哪些证据支持 |
| 不同条件下的结果 | 以少量对应数字量化主发现 | 归纳有效范围、差异及关键取舍 |
| 某指标改善 | 报告有依据的主要结果 | 说明它怎样回答研究问题，避免跨层外推 |
| 尚未验证的方面 | 仅保留影响主张理解的关键条件 | 将真正重要的缺口连接到具体后续验证 |

结论各段可分别承担工作概括、主要回答、解释或边界、后续问题，不规定固定段数。完整中英示例及段落作用见 [连贯案例](writing-examples.md#摘要结论与结果的连贯示例)。

### 结果描述：把数字组织成可判断的发现

#### 先交代理解比较所需的协议

在方法、实验设置或表注中集中说明研究对象、数据划分、基准、重复单位和聚合顺序。涉及随机训练、多个测试样本与时间序列时，分别说明哪一层求和、哪一层平均、哪一层计算离散程度。累计指标与平均指标按定义处理，不把时间点或同一模型下的多条轨迹直接当成独立训练重复。

用均值的相对差还是逐次相对变化的均值，由分析目的和预定协议决定。二者通常不同，不能在摘要、表格和结论之间换算法却沿用同一数字。配对比较需有合理匹配设计，匹配数据、条件或扰动，不能只因文件里的种子编号相同就认定已控制全部差异。

#### 每段解释一个值得讨论的发现

先确定本段回答的问题，再选择关键比较和数字，解释其对研究问题的含义。可以先提出主发现，也可以先指向图表，再进入比较。不要逐列抄表，也不要只写“效果显著”“表现更稳”。代表轨迹帮助解释过程，总体结论仍需对应总体证据。

多指标方向不同时写明取舍。总体表现改善而某组或某段没有改善时，判断例外是否影响主结论，并在相关位置说明。不同方法拥有的信息不同，例如完整未来信息与在线观测，须在定义基准时交代，不能用“接近最优”隐藏离散精度和信息条件。

| 容易混淆的判断 | 应核对的内容 |
|---|---|
| 均值更低、所有重复更低 | 看逐次分布，均值不能代替每次结果 |
| SD、SE、CI、min–max | 核对统计定义、重复单位和图例，阴影不默认是 SD 或置信区间 |
| SD 更小、统计显著、实际有用 | 分别由离散程度、适当推断和研究尺度判断，不能互相替代 |
| 相对变化、绝对差、百分点 | 写清分母与单位，比例量的绝对差可用百分点表示 |
| 预测误差、闭环控制效果 | 分别验证，不仅凭预测精度判断特征对控制的价值 |
| 较小功率增量、较小爬升率、寿命改善 | 指标定义、采样间隔及证据类型不同，不能换名或直接跨层推断 |
| 跨数据补充验证、无需再训练的迁移 | 核实数据独立性、参数是否冻结和测试流程，准确命名 |

#### 将观察、解释和机制分开

“指标降低”是观察，“可能与某种调节方式有关”是解释，明确归因还需相应实验或推导。消融可以增加某个设计有效的证据，但其能排除哪些替代解释，取决于实际控制的条件。讨论应紧接证据，不用理论词汇填补缺失的实验。

相关条件集中说明一次通常足够。影响当前比较的条件须保留，文件目录、导出过程和“已逐项核对”等制作信息不进入结果正文。

### 公式释义：先说明作用，再解释新增信息

公式前交代它用于描述什么关系、优化什么目标或计算什么指标。已有定义是否正确，要结合原始研究定义、实现和量纲核对。润色不能擅自改变目标函数、权重、归一化或假设，发现疑点时先提出具体问题。

公式后解释理解所需的新量，说明物理含义或数学作用。必要时交代定义域、符号方向、单位、归一化尺度和关键取值。已定义量不重讲，参数表中的全部数值不重列。相邻释义放在连贯段落中，信息较多时用短句，不为每个符号另起一段。

英文释义用 where 引出，大小写、标点和缩进按句法、作者现稿与目标规范处理，不把某份稿件的格式迁移成普遍规则。中文用自然的“其中”等表述，不机械套用英文句法。

**同一变量在相同定义下沿用同一完整符号，同一完整符号只对应一个含义。** 当前量、均值、估计量、分量、归一化量及不同时间点有不同定义，应明确区分。字体、大小写、上下标和修饰符都属于完整符号的一部分。不能因“都表示功率”而合并实际输出和指令，也不能将同一已定义输出在另一节随意换名。

双向检查和跨文件范围见 [符号与公式的一一对应](writing.md#符号与公式的一一对应)。示例展示量纲、权重作用、已定义量去重及完整符号核对，不只演示单一乘法关系。

## 研究叙述与工程记录分开

方法部分需要可复现的定义、公式、关键参数、划分和实验协议。主文按“对象与目标 → 设计选择及其理由 → 数学或实验定义 → 与后文分析的关系”组织，不按脚本运行顺序写流水账。代码目录、文件命名、临时版本、逐项核验、导出流程和任务交接放在本地记录或确有必要的复现材料中。

判断一条细节是否进入正文：删掉它，读者会不会误解方法、比较或结论，研究者能否确定关键实验条件。会影响时保留或放入明确引用的补充材料。只说明团队怎样操作文件时不进入主文。不能为了去掉工程味而删除真正影响复现的模型结构、参数定义或失败处理。

结果部分讨论研究发现，不讨论“如何读取表格”“如何打开附件”“已逐项检查”。用途句可简短交代图表内容，但随后应进入具体比较。用户需要的操作说明和内部验收可在交付信息中说明，不混入论文。

## 避免防御性叙述

先区分三类信息：

| 信息 | 写法与位置 |
|---|---|
| 理解方法或比较所必需的条件 | 在方法、实验设置或对应表注集中定义，例如重新训练、样本数、统计顺序 |
| 限定结论的具体证据边界 | 在受影响的讨论位置直接说明事实，例如提前终止、未测退化或不同环境 |
| 重复自我辩护或空泛提醒 | 删除，尤其是不增加信息的“不能保证”“请谨慎理解”“并非全面更优” |

先写已观察到的事实、差异和含义。局限用具体对象和缺口说明，不以一串否定句收尾。真正影响解释的边界不能因为“不够积极”而隐藏。某个限定只写一次通常就够，后文不在每段重申，不另加“本文严格限定”“为避免误解”等编辑口吻。

研究目的可以是降低设备运行负担，结果只能说明实际测得的功率变化或能量指标。将寿命验证集中为后续研究问题即可，不必在每次提到功率指标时追加一段寿命免责声明。若全文没有提出寿命结论且该边界不影响当前解释，也无需机械补一句否定。

具体修改例子统一见 [学术改写对照](writing-examples.md)。这些是论证与表达判断，不是词语黑名单，也不用于判断作者身份或承诺检测结果。

## 符号与公式的一一对应

插入、迁移或改写公式前，以作者确认的当前正文和研究定义为依据检查符号，不用旧规划覆盖手改。**同一变量或物理量在同一论文的相同定义下只使用一个明确符号，每个完整符号也只对应一个含义**。核对大小写、字体、上下标、帽号、横线、单位和定义域，避免一个量出现多个别名，也避免同一符号代表不同量。上下标、时间索引或修饰符所区分的当前量、均值、估计量、分量或不同时间点是不同定义，不能为追求字面统一而合并。连续时间与离散步索引按各自物理意义保留。对于求和、积分等有明确局部作用域的哑变量，逐式检查其局部定义，不把它误判为全文物理量重名。

1. **插入前**：查看上下文、符号表及相关公式，确认变量的物理含义、量纲、正负号和数学关系。沿用现有完整符号，不自造同义记号。发现不同来源的记号冲突时，先依据当前正文和原始定义核实，未能判定则标出待核实，不猜测替换。
2. **双向核对**：从变量查符号，检查同一量在公式、文字、图表、符号表、补充材料和回复信中是否一致。再从符号查变量，检查同一完整符号是否被用于不同含义。核对向量各分量的顺序与文字、实现一致，尤其区分归一化量与原始物理量，或指令与实际执行量。
3. **释义与迁移**：首次出现的符号解释其含义或作用，已定义的量不重复展开。英文用 where 引出释义，大小写按句法和当前稿件处理，只交代理解所需的关键取值，不重复参数表。相邻释义组织为连贯段落。迁移公式时连同上下标、编号、上下文和释义核对，不只比较外观。
4. **修改及验证**：记录发现的冲突与受影响位置，按授权范围更正并检查跨文件同步。编辑 Word 时保护公式对象、引用域与编号，分别核验数学内容和可编辑性。未经授权的文件只报告需要同步的位置，不自行覆盖。

修订颜色和标记遵循当前项目及作者最新确认的规则。引用域、编号、公式对象和原有颜色须保护，不能因整段标记而破坏这些对象。

## 可追溯性

- 记录源文件、版本或哈希、工作表/字段、筛选范围、实验设置、计算脚本、单位和聚合顺序。分别标记事实、推断、待核实。
- 区分单个样本、重复实验、群体统计以及均值、标准差、区间的定义。统计方法由设计和数据决定，不把某种统计量作为所有论文的强制条件。
- 按源代码、配置及真实运行记录校对公式、变量、观测与动作定义，历史运行版本未知时明确限定。符号字母、下标、单位、采样间隔和正负号全文统一。
- 文献逐条核对作者、年份、题名、出处、DOI 和原文支持，不能凭搜索摘要编造结论。新文献、原始引用域及文末条目分别追踪。
- 中文学术表述准确自然，避免空话、重复及无证据拔高。保留作者表达、限定和信息，不承诺检测结果。标点遵循当前作者、学校和项目的要求。

## 文献学习与经验来源

本指南区分四类依据：作者与导师已确认的偏好、从实际修稿过程归纳的经验、公开论文中观察到的写法，以及通用写作资料。英文短句、方法与评价优先自然被动、少用第一人称和 where 释义属于作者偏好。多条件结果分开写、明确统计层级、以证据组织结论、以成稿同步符号，是修稿过程中形成的可迁移经验，不把每一条都声称为导师原话。结论开头约四句、释义顶格小写曾是个别稿件的建议，不是通用格式。

优先利用本地相关领域全文，再按需补充高水平跨领域论文。读摘要、关键结果、结论和公式附近的文字，记录它如何支持一个判断，同时记下不可迁移的事实。期刊水平不保证每个句子、数字或符号都可直接借用。发现疑点需单独核实，不继承疑点，也不未经复核就宣布论文有误。补引和元数据核验见 [文献工作流](literature.md)。

公开论文的元数据、实际阅读位置及写法观察集中在 [文献阅读记录](literature.md#写作参考论文的阅读记录)，可借鉴的原文短例集中在同一文献指南中。写作时按任务读取，不为一次润色重新阅读所有来源，也不自动把这些文献加入用户论文。

## 交付检查

1. 本段新增了什么必要信息？与相邻段是否共同回答一个问题？只有重复就精简，作用相同且合并更连贯就合段，不为短句或留白拆散论证。
2. 读者能否看懂比较为什么成立、结果意味着什么？存在逻辑断点就补解释或证据。
3. 有无把假设写成事实、代理写成直接结论、计划写成完成，或把编辑过程写入正文？逐项对照源材料修正。

按本轮范围核对研究对象、比较条件、统计层级、数值、单位、时间、否定、归因与结论强度，保留失败与不一致观测。摘要、结果、结论和相关文件的关键事实一致，公式、释义、图表和符号表双向对应。用户只要求文字版或先审批时，不擅自写回稿件。

事实核查、对象保护和页面验收分别报告。仅有语言材料时不声称统计、公式对象或页面已经验收。编辑和排版见 [Word 工具](word-tooling.md)，正文、SI 与回复联动见 [返修流程](revision-workflow.md)。完整改写或全篇审查可按需参考 [PaperSpine 改写](../embedded/paper-spine-rewrite/SKILL.md) 与 [审查](../embedded/paper-spine-audit/SKILL.md)，不自动引入额外交付或检测分数目标。
