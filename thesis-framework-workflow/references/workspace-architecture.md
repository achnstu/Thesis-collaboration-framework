# 论文工作区架构

用途：从研究资料搭建可追溯的学位论文工作区，或理解现有工作区。该结构是建议，不限定章数、学科或软件。用户指定位置、已有项目结构及适用规则优先。仅写一段、修改一图等局部任务，无须创建整套目录。

## 开始前

1. 明确论文范围、工作区位置、当前主稿、已有数据与结果、学校模板、用户要求的交付物。登记已有路径、版本、责任人和使用权限。
2. 检查现有目录和项目规则。已有工作区优先建立索引与映射，复用已存在的目录，不因结构不同就复制、移动或重命名。记录主稿的真实路径和版本，不凭文件名“最终版”认定当前稿。
3. 新建工作区或获用户要求组织资料时，按实际工作创建必要目录。用户要求复制、迁移或整理时，先列明来源、目标、处理方式及冲突，保护原件、人工编辑和历史版本。涉及删除时遵循项目删除规则。
4. 根据当前目录创建工作入口，链接主稿、规范、章节规划、数据来源、图表计划、符号表和待办。路径失效或资料未取得时标记状态，不虚构来源。

## 建议目录树

```text
论文工作区/
├── README.md                  # 当前入口：主稿、规范、进度与索引
├── 01_规范与参考/
│   ├── 学校模板与要求/        # 学校格式、导师意见与参考范文索引
│   └── 已有成果/              # 可用的小论文、报告及其版本索引
├── 02_论文稿件/
│   ├── 当前稿/                # 用户指定的现行文稿和相应记录
│   ├── 章节底稿/              # 按章组织可编辑底稿
│   └── 版本快照/              # 有意义的阶段性备份与修改说明
├── 03_数据与证据/
│   ├── 来源索引/              # 原始来源、版本、权限和哈希
│   ├── 原始资料副本/          # 仅在有需要和权限时复制，保持只读
│   └── 派生数据/              # 统计表、筛选和计算结果，按章或实验组织
├── 04_图表/
│   ├── 图表规划/              # 稳定定位号、章节、图号和来源映射
│   └── 按章图表/              # 每章的源工程、导出、代码和验收
├── 05_文献/
│   ├── 文献索引与引用/        # 文献库导出、元数据和论点支持记录
│   └── 原文资料/              # 按许可保存，或仅记录链接及本地位置
├── 06_写作管理/
│   ├── 章节与证据映射/        # 章节职责、研究问题和论点证据
│   ├── 符号与公式/            # 符号定义、单位、公式和字段映射
│   ├── 修改与验收/            # 修改记录、数据核验、版式检查和未决项
│   └── 协作与交接/            # 按需：协调台账、任务卡、状态与经验记录
└── 07_交付/                   # 用户指定的阶段成果与交付清单
```

名称可根据团队习惯调整，不强制使用数字前缀。`01_规范与参考` 和 `05_文献` 保存参考材料及索引，`03_数据与证据` 管理实际研究数据和计算，`02_论文稿件` 管理正文，`04_图表` 管理可编辑图与输出，`06_写作管理` 维护跨文件对应关系。不要把整个实验归档复制进论文目录，优先引用现有正式来源。

## 图表按章组织示例

```text
04_图表/按章图表/第3章_方法与结果/
├── 图表索引.md                # 定位号、正式图号、当前版本和来源
├── 数据及来源/                # 派生绘图数据与原始数据位置
├── 绘图代码/                  # 绘图与统计脚本、依赖、参数
├── 可编辑工程/                # 如 OPJU、FIG、PPTX，按实际工具选用
├── 输出图/                    # 预览及论文插图，版本与工程对应
└── 验收记录/                  # 数值、回开、图面、灰度和 Word 检查
```

可编辑工程和输出图可按既有习惯放在同一位置，不要求生成所有格式。每幅图应能追溯到数据、筛选、统计顺序、软件版本和代码。保留用户手工调整，不能用旧脚本无提示覆盖较新的工程。独立研究示意图记录内容来源和可编辑原文件，数据图另保存数据与计算依据。

## 文件命名与版本

- 稳定材料 ID 与论文中的图表编号分开，例如 `C3-D01` 是数据图定位号，`图3-2` 是当前论文编号。编号变化时同步索引、正文、图题和相关代码，不能按文件名猜内容。
- 名称写清主题、版本或日期，例如 `C3-D01_训练过程_v02.opju`、`图表规划_20261028.md`。编号和日期仅作示例，实际以项目既有规则为准。存在多个版本时由索引记录哪个是当前版本及确认依据。
- 主稿修改前保留可恢复版本，记录输入、输出、修改范围和日期。备份后核实文件存在、大小和必要时哈希，不以空目录或历史记录代替备份。
- 数据来源索引至少包含：源路径或持久标识、文件版本/哈希、表和字段、数据范围、筛选、统计定义、复制位置及权限。派生数据保留生成脚本、参数和输入版本，原始数据不被改写。
- 文献索引记录元数据、DOI 或链接、原文位置、支持的论点与核验状态。受许可限制的论文和数据可仅记录引用及所在位置，不默认复制或公开分发。

## 建立与维护

1. 先建立入口和必要的稿件、写作管理、证据索引，再根据已有数据、图表或文献创建对应目录。不创建大量空文件夹充当完成成果。入口可按 [工作区入口模板](../assets/templates/workspace-entry.md) 填写，链接以实际位置为准。
2. 按 [论文规划模板](../assets/templates/thesis-planning.md) 建立章节与材料对应关系。图表记录采用 [图表模板](../assets/templates/figure-record.md)，正文和正式图号在索引中链接。
3. 新增或修订证据时，沿“来源 → 派生表 → 图表 → 正文 → 摘要与结论”追踪影响。修改记录写明更改原因、范围、核验结果及未完成事项。
4. 多人协作时标识当前主稿、负责人和锁定状态，尽量让各人分别维护所属材料。合并前核对输入版本及人工修改，保留可恢复副本。
5. 阶段交付核对清单、相对链接、输入输出、源数据保护、可编辑性和页面效果。明确哪些仅完成结构检查，哪些实际打开或渲染过。

明确需要多对话协作时，按 [多对话协作与证据理解](multi-chat-collaboration.md) 建立任务和交接记录。现有工作区已有对应目录时沿用，不重复创建。

## 本项目实例

当前 Markov-DRL 项目已有 `大论文/初稿`、`数据表`、`图表文件夹`、`文献池`、`写作管理` 及根目录主稿。先读该目录现行 README 与项目规则，沿用已有分类和作者当前文件，不把上面的通用树直接套用到现有项目。实际状态和入口以当前文件为准。
