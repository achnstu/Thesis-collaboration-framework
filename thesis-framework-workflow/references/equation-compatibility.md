# Word 公式的空格与上横线兼容检查

触发词: “公式转 MathType 乱码”, “公式黑菱形”, “特殊空格”, “零宽字符”, “上横线丢失”, “目标参数横线”。

适用于新生成或局部修复的 Word 原生 OMML，尤其是后续需要转 MathType 的公式。沿用作者确认的完整符号，只修复表示结构，不据此改写算法。已有 MathType/OLE 对象按 [Word 对象保护](word-tooling.md) 处理，不将其当作 OMML 重建。

## 已遇到的问题与处理顺序

Word 能显示的 OMML 不一定能被 MathType 等价转换。实际案例同时存在特殊空格、清理后残留的空数学 run，以及用 U+203E OVERLINE 表示的上横线重音。只去掉空格会遗漏后两类问题。修复应覆盖下面三个检查点，不能仅检查源码中是否写了 `\bar`。

1. **检查公式内的空白载荷。** 读取相关 XML 中 `m:t` 的字符，列出可疑码位。已遇到 U+2001 EM QUAD、U+2005 FOUR-PER-EM SPACE、U+200B ZERO WIDTH SPACE。确认它们仅用于数学排版时再移除。公式内的多词文本、普通空格和正文间距按含义保留，不在整个文档上执行空白或格式字符的全局删除。
2. **清理残留空节点。** 去除排版字符后，删除没有数学文字且不承载其他内容的空 `m:r`。不要删除必要的表达式容器、分式分母、矩阵单元或占位结构。保持原有公式对象及其位置。
3. **将上横线表示为原生结构。** 对本来表示上横线的 `m:acc/m:accPr/m:chr`，若其值为 U+203E，改为顶部 `m:bar`。其他重音不机械替换。保留原 `m:e` 子树，以及适用的 `m:ctrlPr` 字体与字号属性。

## 上横线的结构约定

下例省略命名空间声明和样式属性，只展示结构差别。实际修改应复制原节点及属性，不用这段简写覆盖整条公式。

不继续沿用的上横线重音写法：

```xml
<m:acc>
  <m:accPr><m:chr m:val="&#x203E;"/></m:accPr>
  <m:e><m:r><m:t>θ</m:t></m:r></m:e>
</m:acc>
```

兼容修复采用顶部横线对象：

```xml
<m:bar>
  <m:barPr><m:pos m:val="top"/></m:barPr>
  <m:e><m:r><m:t>θ</m:t></m:r></m:e>
</m:bar>
```

横线属于参数时，仍须保留在参数上。例如 `\mu_{\bar{\theta}}` 的横线只作用于下标参数，不能改成整个网络输出的横线，不能删除横线或改用相似字符代替。均值横线、目标参数横线及其他修饰符均按作者原始定义核对，不因外观相似而合并含义。

## 保存与定向验证

- 输出到新的候选文件，保留源稿。直接编辑 OOXML 时只改目标 XML 成员，保护关系、媒体、引文域和 OLE。实现脚本放任务或技能的 `scripts/`，不散落在项目主目录。
- 比较修复前后的数学文字、公式对象数量、上下标层级、横线作用对象和横线数量。忽略已确认的排版空白时，其他数学文字应一致。文字相同不能单独证明横线结构或公式含义正确。
- 检查已处理范围中不再有目标特殊空白、相应空 run 或 U+203E 上横线重音。已有正确的 `m:bar` 不重复改写，处理应可重复执行而不改变已修复结构。
- 查看受影响公式的实际显示，尤其是带横线的下标参数、嵌套网络调用和软更新式。Word 显示检查与 MathType 转换检查分别记录，不将其一报成另一项通过。
- 需要并已获授权验证 MathType 时，先用少量代表公式在副本中转换，核对横线、上下标、希腊字母和可编辑对象，再决定是否扩大转换。黑菱形、问号或横线缺失时保留失败样例，比较转换前后结构，不直接认定原算法公式有错。
- 作者接管或免除显示检查时遵从其要求，交付已完成的结构修复并准确说明检查范围。作者确认可用的局部修复可复用，但不推广为所有 Office 或 MathType 版本均已实测。
